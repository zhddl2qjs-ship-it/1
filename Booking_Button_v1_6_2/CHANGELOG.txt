변경 이력

v1.6.1 변경

- 성능: 버튼과 상관없는 곳이 계속 바뀌는 페이지(실시간 시계·배너 등)에서, 앞에 보이는 탭은 프레임 루프에 맡기고 따로 확인하지 않게 했습니다. 가려진 탭과 고속 감시 구간은 그대로 확인합니다.
- 아이콘을 누르면 팝업이 열리면서 패널이 바로 열립니다(클릭 하나 절약). 실패하면 팝업의 ‘다시 열기’ 버튼으로 다시 시도합니다.
- 버튼을 고르거나 감시를 시작했을 때 패널이 버튼을 가리면 반대쪽으로 자동으로 옮깁니다.
- 감시 시작 전 ‘현재 감지’ 문구를 ‘유채색’ 대신 ‘읽은 색’으로 바꿨습니다(연한 회청색 대기 버튼이 ‘유채색’으로 보여 헷갈리던 문제).
- 감시 중 작은 패널의 상태 문구를 짧게 줄였습니다.
- 내부: 내부 키를 V8 → V9 로 올렸습니다.

v1.6.0 변경

- 알림음: 클릭을 보냈을 때(높은 두 음)와 감시가 저절로 멈췄을 때(낮은 세 음)를 다른 소리로 알립니다. 직접 중지(Esc·중지·닫기)하면 울리지 않습니다. 패널에서 끄거나 미리 들어볼 수 있습니다.
- 주소 변경 감지 완화: 주소(경로)만 바뀌었다고 감시를 멈추지 않습니다. 버튼이 남아 있으면 계속 감시하고, 주소가 바뀌었는데 버튼이 사라졌으면 즉시 멈춥니다.
- 기준색 색상 견본: 시작 전에는 ‘지금 색’, 감시 중에는 ‘대기 기준’과 ‘현재’ 색을 보여 줍니다.
- 타이머 모드: 카운트다운이 끝난 뒤 글자가 마감·종료·매진 등이면 클릭하지 않고 기다립니다(‘마감임박’은 제외).
- 확장프로그램 아이콘을 추가했습니다(16·32·48·128px).
- 감시 중 작은 패널에서 ⇄ × 버튼이 상태 문구를 가리던 문제를 고쳤습니다.
- 사용 안내 문단을 접어 두었습니다. README 의 변경 이력을 이 파일로 옮겼습니다.
- 내부: 이미 이전 버전이 주입된 페이지에서도 새 코드가 우선하도록 내부 키를 V7 → V8 로 올렸습니다.

v1.5.2 변경

- 이미지 버튼의 평소 화면 캡처 주기를 550ms에서 1100ms로 늘렸습니다. Chrome은 화면 캡처를 1초에 2회까지만 허용하는데, 550ms 주기가 그 한도를 거의 다 써서 ‘버튼 근처가 바뀌면 즉시 캡처’가 작동할 자리가 없었습니다(변경 알림이 있는 이미지 버튼도 주기 확인과 똑같이 느렸습니다). 한 자리를 비워 두어, 클래스·이미지 교체 등 변경 알림이 있는 이미지 버튼은 변화 뒤 약 0.1초에 감지합니다.
- 대신 바뀔 때 페이지에 아무 알림도 없는 캔버스·영상 버튼은 평소 확인이 느려집니다. 그런 버튼이면 패널의 ‘캔버스·영상 버튼’을 켜세요(0.55초 주기). 이 옵션을 켜면 변경 알림이 있는 이미지 버튼은 반대로 느려집니다. 어느 쪽인지 모르겠으면 기본 설정으로 시작해 보고, 이미지가 바뀌었는데 한참 뒤에야 잡히면 옵션을 켜 보세요.
- 화면 캡처 형식을 PNG에서 JPEG(품질 92)로 바꿨습니다. 버튼 안쪽 몇 지점의 색만 읽으므로 충분하고(단색 면의 색 오차 1단계 이하) 인코드·디코드가 빨라집니다. 실제 Chrome에서의 단축 폭은 측정하지 못했습니다.
- 색 전환·애니메이션 확인을 화면 프레임이 갱신되는 순간(그리기 직전)에 맞췄습니다. 예매 시간 근처 고속 구간과 프레임이 멈춘 탭에서는 기존 보조 타이머가 함께 확인합니다.

v1.5.1 변경

- 연한 회청색 대기 버튼을 ‘이미 활성 색상’으로 오인해 감시를 시작하지 못하던 오류를 수정했습니다.
- 감시 시작 순간의 색을 기준으로 비교합니다. 색상이 있다는 이유만으로 시작을 막거나 바로 클릭하지 않습니다.
- 작은 색상 흔들림과 외부 덮개의 색상 변화는 걸러냅니다. 회색·회청색 대기 덮개가 사라져 버튼색이 드러나는 경우도 확인합니다.
- v1.5.0의 빠른 변경 감지를 유지합니다. 버튼 자체나 주변의 색상·활성 상태 변경 알림이 오면 별도 대기 간격 없이 바로 확인합니다.
- 변경 알림이 없는 CSS 전환·애니메이션 등은 화면 프레임이 갱신될 때마다(60Hz 화면에서 약 16ms) 확인합니다. 브라우저 상태에 따라 늦어질 수 있습니다.
- 클릭 전에 패널을 펼치던 작업을 클릭 이후로 옮겼습니다.
- 버튼을 가린 요소의 색만 바뀌어 잘못 클릭하는 경우를 줄였습니다. 가려진 버튼을 일정 시간 뒤 강제로 클릭하던 동작은 제거했습니다.

검증 결과

제보된 색상 조합과 색상 판단은 실제 소스의 함수를 Node.js에서 실행해 검사합니다. Mac 업데이트는 Objective-C 연결을 대신하는 테스트용 모형으로 검사합니다. 이 버전의 브라우저 통합 검사는 실행 환경의 권한 제한으로 실행하지 못했습니다. 실제 Mac·Chrome 화면 캡처 API·예매 사이트에서 직접 검증한 결과는 아닙니다. 먼저 동봉된 demo.html에서 한 번 클릭되는지 확인하세요.

v1.5.2 측정 (참고용)

헤드리스 Chromium에서 화면 캡처 API를 ‘80ms 걸리고 초당 2회로 제한되는’ 모의 객체로 바꿔 측정했습니다. 변화가 일어난 순간부터 버튼 클릭 이벤트까지의 시간이며, 칸마다 14~20회 평균입니다. 실제 Chrome의 화면 캡처 API와 실제 예매 사이트에서 잰 값이 아닙니다.

- 일반 버튼(클래스·스타일·CSS 변수 변경): 약 3ms. 무거운 페이지 약 7ms. v1.5.1과 거의 같습니다. 새 프레임 확인 때문에 즉시 변경 경로가 평균 0.2~0.8ms 늘었고, 대신 CSS 전환 70→62ms, 알림 없는 스타일시트 변경 16→11ms로 줄었습니다.
- 변경 알림이 있는 이미지 버튼(감시 시작 후 충분히 지난 뒤): v1.5.1 430ms(최악 636ms) → v1.5.2 95ms(최악 99ms).
- 변경 알림이 없는 캔버스형 이미지 버튼: 기본 설정에서 426ms → 506ms로 느려지고, ‘캔버스·영상 버튼’을 켜면 386ms입니다.
- 예매 시간 입력(고속 구간)에서도 같은 방식으로 오류·중복 클릭 없이 한 번만 클릭되는 것을 확인했습니다.

화면 캡처 형식(JPEG) 변경의 속도 이득은 실제 captureVisibleTab으로 재지 못했습니다(대리 측정에서는 1080p 인코드+디코드 106→62ms). 실제 Mac·Chrome에서 먼저 demo.html로 확인하세요.
