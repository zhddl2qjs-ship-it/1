검증결과 — Booking_Button v1.6.2

최종 watcher.js를 Chromium에 주입한 UI 통합 검사 23개 통과(핵심 18 + 배포 DOM 데모 5).

핵심 검사:
- disabled 해제 시 색상 변화 없이 한 번 클릭
- 클래스와 문구가 다른 새 예매하기 버튼으로 교체
- 기존 대기 요소가 숨고 새 버튼이 나타나는 경우
- 이미 활성인 버튼에서 시작 거부
- 다른 위치의 버튼을 잘못 클릭하지 않음
- disabled인 동안 색상만 변해도 클릭하지 않음
- 중지·Esc 뒤 클릭 없음
- aria-disabled·inert 해제
- 여러 변경 알림에서 한 번만 클릭
- 기존 색상 모드에서 색상 전환 시 한 번 클릭
- 버튼 가림 해제 뒤 처리
- 같은 자리 예매 취소로 교체 시 클릭 없음
- 같은 ID의 취소 버튼으로 교체 시 클릭 없음
- 같은 요소의 문구가 예매 취소로 바뀌어 활성화되면 클릭 없이 중지
- 예매내역 조회 버튼으로 교체 시 클릭 없음

배포 DOM 데모 5경로:
same / unchanged / replace / rerender / attributes 모두 통과.
DOM 모드의 화면 캡처 요청은 모든 검사에서 0회.
독립 검토에서 취소 버튼으로 잘못 교체 매칭하던 경로를 발견·수정하고 음성 회귀 검사에 반영.

검사 환경과 한계:
- Linux의 Headless Chromium + Playwright, 실제 watcher.js와 패널 UI를 사용.
- Chrome runtime API는 mock. 데모 검사는 가상 타이머를 사용.
- 실제 macOS Chrome의 설치·activeTab 권한·툴바 아이콘·다른 출처 프레임 접근과 놀티켓 동작은 미검증.
- 로컬 검사 지연값은 실제 놀티켓의 반응 시간이나 예매 성공률이 아님.
- 기존 대기 버튼이 숨겨지거나 제거되는 교체는 지원. 기존 비활성 버튼이 계속 보이는 채로 새 버튼이 겹치는 화면은 현재 기존 버튼을 계속 기다릴 수 있음.
- 위치가 크게 바뀌거나 대체 버튼 문구가 알려진 예매 동작 문구와 다르면 재선택 필요.
