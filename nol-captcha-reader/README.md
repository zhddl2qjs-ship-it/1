# NOL 캡차 자동 입력 1.0.3

제공된 NOL 예매 HTML 구조에 맞춘 Chrome / Edge 116 이상용 확장프로그램입니다.
캡차 이미지가 나타나면 로컬 OCR로 읽고, 입력창에 입력한 뒤 같은 모달의 활성화된 **입력완료** 버튼을 한 번 클릭합니다.

## macOS / Linux 터미널 설치

아래 명령을 그대로 실행하세요. 실행 시 고정 버전 OCR 엔진과 모델 약 16MB를 다운로드하고 파일을 검증합니다. 기존 기본 경로에 설치되어 있으면 백업한 뒤 같은 폴더를 업데이트합니다.

```bash
mkdir -p "$HOME/Downloads"
curl --fail --location 'https://raw.githubusercontent.com/zhddl2qjs-ship-it/1/codex/nol-captcha-reader-v1.0.0/nol-captcha-reader/install.sh' -o "$HOME/Downloads/nol-captcha-install.sh" &&
bash "$HOME/Downloads/nol-captcha-install.sh"
```

1. Chrome의 `chrome://extensions` 또는 Edge의 `edge://extensions`를 엽니다.
2. **기존 설치 업데이트:** NOL 캡차 확장프로그램 카드의 **새로고침(↻)** 버튼을 누르고 버전이 **1.0.3**인지 확인합니다.
3. **처음 설치:** 개발자 모드를 켜고 **압축해제된 확장 프로그램 로드**에서 스크립트가 출력한 설치 폴더를 선택합니다. 새 설치의 기본 경로는 `~/Downloads/nol-captcha-reader-1.0.3`입니다.
4. 열려 있던 예매 페이지도 새로고침합니다. 이전 내용 스크립트는 확장프로그램만 새로고침해서는 교체되지 않습니다.
5. 확장프로그램 오류 화면에 이전 기록이 남아 있으면 기존 기록을 지운 뒤 새 캡차에서 다시 확인합니다.

브라우저 등록은 화면에서 한 번 직접 해야 합니다. 처음 설치하면 자동 인식과 자동 클릭이 켜져 있습니다.
설치한 폴더는 사용하는 동안 삭제하거나 이동하지 마세요.
기존 기본 설치 폴더 `~/Downloads/nol-captcha-reader-1.0.0`, `~/Downloads/nol-captcha-reader-1.0.1` 또는 `~/Downloads/nol-captcha-reader-1.0.2`가 있으면 그 경로를 유지합니다. 따라서 Chrome에 확장프로그램을 다시 등록할 필요가 없습니다. 다운로드·검증이 끝난 후에만 교체하며, 이전 파일은 별도 백업 폴더에 보관합니다. 다른 경로에 설치했으면 해당 설치 폴더를 직접 지정하세요. 다른 프로그램의 폴더는 덮어쓰지 않습니다.

```bash
bash "$HOME/Downloads/nol-captcha-install.sh" "/기존/확장프로그램/설치폴더"
```

## 1.0.3 수정 사항

OCR 엔진이 내장된 WASM 바이트를 `data:application/octet-stream;base64,...` 주소로 읽을 때 확장프로그램의 `connect-src 'self'` 정책이 이를 차단했습니다. 이 `data:` 주소는 파일에 포함된 데이터를 나타내며 외부 인터넷 서버 주소가 아닙니다. 이전 버전은 Base64를 직접 읽는 대체 경로로 인식을 계속할 수 있지만, 차단 오류는 콘솔에 남을 수 있었습니다.

`connect-src 'self' data:`로 수정해 내장 데이터 읽기를 허용했습니다. 외부 서버 연결이나 원격 스크립트 실행 허용은 추가하지 않았습니다. 업데이트 후 확장프로그램과 예매 페이지를 새로고침하고, 기존 오류 기록을 지운 뒤 새 오류가 발생하는지 확인하세요.

## 1.0.2 수정 사항

- 글자와 비슷한 색의 겹친 선을 별도로 처리하고 여러 판독 결과를 교차 확인합니다.
- 판독이 불확실하거나 영문 6글자를 얻지 못하면 기존 입력을 지우고 **새 문자 불러오기 → OCR → 입력 → 입력완료** 순서로 재시도합니다.
- 사이트가 오답 메시지를 표시하면 같은 절차로 재시도합니다. 이미 이미지가 바뀌었다면 이전 입력을 지우고 바뀐 이미지를 사용합니다.
- 무한 반복을 피하도록 기본 최대 재시도는 5회입니다. 팝업에서 자동 재시도를 끄거나 0~20회로 조절할 수 있습니다.
- 새 문자 버튼을 눌렀는데 이미지가 바뀌지 않으면 이전 이미지를 재제출하지 않고 멈춥니다. 사용자가 직접 입력하거나 확장프로그램을 끄면 대기 중인 자동 처리를 취소합니다.

## 1.0.1 수정 사항

`이미지를 읽는 시간이 초과되었습니다` 오류가 발생하던 DOM 이미지 디코딩 대기 경로를 제거했습니다. 이제 실제 이미지 바이트로 PNG/JPEG 형식을 판별하고 `createImageBitmap`과 `OffscreenCanvas`로 처리합니다. 제한 시간을 늘리는 방식은 사용하지 않았습니다.

새로 제공한 캡차 `CTXCNA`와 기존 세 이미지에서 인식·React 입력·버튼 클릭 테스트가 통과했습니다. 일반 브라우저와 숨긴 iframe에서는 기존 오류 자체를 재현하지 못했으므로, 실제 Chrome offscreen 환경이 정확한 원인인지는 아직 확인하지 못했습니다.

## 동작과 설정

- 대상 사이트: `https://tickets.interpark.com/*`
- 입력창: `input[class*="ModalCaptchaText_captchaInput"]`
- 공통 모달: 가장 가까운 `[class*="ModalLayout_innerWrap"]`
- 이미지: 모달 안의 `[class*="ModalCaptchaText_captchaImage"] img[alt="캡챠 이미지"]`
- 제출: 같은 모달에서 텍스트가 `입력완료`인 활성 버튼

정답은 DOM 텍스트에 들어 있지 않아 이미지 OCR이 필요합니다. 문자·배경·겹친 선을 구분하고 여러 전처리 결과의 판독을 비교합니다. 서로 맞지 않는 후보를 무조건 제출하지 않습니다.
Native input setter와 `input` / `change` 이벤트로 React에 값을 전달하고 버튼 활성화를 기다립니다.
사용자가 편집 중인 값은 덮어쓰지 않습니다. 오답으로 표시된 이전 값과 확장프로그램이 입력한 오래된 값은 재시도 전에 비웁니다. 인식 중 이미지가 바뀌면 이전 인식 결과를 폐기합니다. 같은 이미지는 반복 제출하지 않습니다.

확장프로그램 아이콘에서 자동 인식·자동 클릭·자동 재시도를 각각 끌 수 있습니다.
재시도 횟수를 소진했거나 직접 입력해서 자동 처리가 멈췄다면, 입력창을 비우고 팝업의 **자동 처리 다시 시작**을 누르면 새 작업으로 시작합니다.

## 검증과 범위

1.0.3에서는 OCR 작업자에 동일한 CSP를 적용해 이전 설정의 `data:` 읽기 차단을 재현했습니다. 수정 후 내장 WASM 읽기와 이미지 8개 인식이 성공했고, 작업자의 CSP 위반은 없었습니다.

실제 브라우저 OCR에서 제공된 이미지 8개와 F/P·C/T 구분용 합성 이미지 4개를 확인했습니다. 제공된 8개 모두 실제 React 입력창 반영과 버튼 클릭까지 통과했습니다. 재시도 시나리오 18개와 기존 입력 제어 검사 17개, 설치 업데이트·백업·실패 복구 검사도 통과했습니다.
실행 환경의 Chromium 관리 정책으로 확장프로그램 설치가 차단되어 실제 설치 상태 검증은 완료하지 못했습니다. 실제 예매 서버에 인증을 제출하지 않았습니다.
새 이미지의 인식 정확도나 인증 성공을 보장하지 않습니다. 자세한 내용은 [VALIDATION.md](VALIDATION.md)를 참고하세요.

## 구성

- `install.sh`: 검증된 소스가 포함된 설치 스크립트. OCR 라이브러리·모델을 다운로드한 뒤 SHA-256을 확인합니다.
- `src/`: 읽을 수 있는 원본 확장프로그램 소스. `vendor/` 런타임 파일은 설치 스크립트가 설치 폴더에 준비합니다. `src/`만 바로 로드하면 작동하지 않습니다.
- `THIRD_PARTY_NOTICES.md`: 사용한 라이브러리 및 모델 정보.

설치 후 OCR은 기기 안에서 실행되며 이미지를 외부 OCR 서비스로 보내지 않습니다. 원본 예매 HTML·캡처 이미지·로그인 정보는 이 배포에 포함하지 않았습니다.
