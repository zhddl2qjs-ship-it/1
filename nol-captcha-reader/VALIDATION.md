# 검증 결과

최근 검증일: 2026-11-02 (한국 시간)

## 1.0.3 내장 WASM의 CSP 차단 수정

사용자가 제공한 오류 화면은 `data:application/octet-stream;base64,...` 읽기가 `connect-src 'self'`를 위반한다는 내용이었습니다. 첨부한 소스는 배포한 Tesseract-core 5.1.1 SIMD-LSTM 파일과 바이트 단위로 같았습니다.

엔진은 JavaScript에 내장된 WASM 바이트를 `fetch(data:...)`로 읽습니다. 확장프로그램의 `connect-src 'self'`에는 `data:`가 포함되지 않아 이 읽기를 차단했습니다. 엔진이 Base64 직접 디코딩으로 대체할 수 있어 오류가 기록되어도 OCR은 성공할 수 있습니다.

`connect-src 'self' data:`로 수정했습니다. `script-src`, worker 제한, 사이트 접근 범위와 OCR 로직은 그대로입니다. `data:`는 내장된 데이터를 읽는 방식이며 원격 OCR 서버를 추가하지 않습니다.

### 확인한 결과

- 실제 Chromium의 전용 작업자 응답에 CSP HTTP 헤더를 적용해 이전 정책의 차단을 재현했습니다. 내장 WASM의 fetch가 `TypeError: Failed to fetch`로 실패하고 `securitypolicyviolation`에 `connect-src` / `data`가 기록됐습니다. 대체 경로로 OCR이 성공하는 것도 확인했습니다.
- 수정한 정책에서는 같은 내장 WASM fetch가 성공했고 작업자의 CSP 위반이 없었습니다. 제공된 이미지 8개가 모두 올바르게 인식되어 자동 입력 조건을 통과했습니다. 외부 네트워크 요청이나 미처리 예외는 없었습니다.
- 이전 문서의 CSP 검증은 주로 일반 문서의 meta 정책에 의존해 전용 작업자의 차단을 놓쳤습니다. 이번 검사는 작업자 자체의 정책과 실제 fetch 결과를 확인합니다.
- 1.0.3 설치 파일의 업데이트·백업·실패 복구 검사가 통과했습니다. 설치된 소스로 CSP를 작업자 응답에도 적용한 실제 OCR·React 입력·클릭 검사에서 8개 이미지가 통과했습니다.

관리 정책으로 실제 Chrome 확장프로그램 설치는 여전히 미검증입니다. 위 결과는 작업자에 동일한 CSP를 적용한 브라우저 재현 검사이며 실제 예매 서버 인증 결과는 아닙니다.

## 1.0.2 인식 및 자동 재시도 수정

### 인식 검증

- 제공된 이미지 8개 모두 실제 Chromium 및 배포용 Tesseract.js WASM에서 올바른 영문 6글자로 인식되고 자동 입력 조건을 통과했습니다.
- 겹친 선 제거, 가려진 짧은 획 복구, 작은 잡음 제거 후 전체 줄/잘라낸 단어 형태의 6개 판독을 비교합니다. 서로 다른 처리 결과의 일치와 최소 신뢰도를 확인하며, 유력한 다른 후보가 있으면 자동 입력하지 않습니다. 신뢰도 수치는 정답 확률이 아닙니다.
- 실제 F/P 및 C/T가 포함된 별도 합성 이미지 4개도 통과했습니다. 이미지별 정답을 저장하거나 F를 P로 일괄 치환하는 방식은 사용하지 않습니다. 판독 불일치·낮은 신뢰도·유효하지 않은 길이를 포함한 판정 조건 5개도 확인했습니다.
- 동일한 CSP 아래 일반 페이지 및 숨긴 iframe에서 8개 이미지를 확인했습니다. DOM 이미지 디코딩을 사용할 수 없도록 해도 처리되며, 잘못 표시된 MIME 보정·손상된 입력 거부·늦게 디코딩된 bitmap 해제를 확인했습니다. 외부 OCR 요청은 없었습니다.
- 실제 React 18 controlled input, OCR, background/offscreen 메시지 핸들러를 연결한 검사에서 8개 이미지가 각 한 번 입력·클릭되었습니다. Chrome API는 테스트 대역입니다. 이미지가 없는 관계없는 버튼은 클릭하지 않았습니다.

### 재시도 동작

인식 실패·불확실한 결과·새로운 서버 오답 표시가 있으면 이전 입력을 비운 뒤 같은 모달의 새 문자 버튼을 누릅니다. 실제 이미지 소스 변경을 기다린 뒤 다시 인식합니다. 서버가 이미 이미지를 바꿨다면 추가 새로고침 없이 새 이미지를 사용합니다. 기본 재시도 한도는 5회이며 팝업에서 0~20회로 설정할 수 있습니다.

이전 요청의 오류 메시지가 그대로 남아 있다는 이유만으로 새 제출을 실패로 간주하지 않습니다. 새 이미지가 오지 않으면 중단하고, 사용자가 직접 입력하거나 자동 인식을 끄면 대기 중인 처리를 취소합니다. 입력창이 다시 생성되어도 재시도 횟수를 유지합니다.

재시도 시나리오 18개가 통과했습니다. 인식 오류·불확실한 결과·늦은 서버 거절·이전 오류 유지·서버의 이미지 교체·초기 오답 입력·횟수 제한·새 이미지 대기 시간 초과·직접 편집·비활성화·입력창 재생성·수동 새 문자 요청·모달 종료를 포함합니다. 자동 재시도를 끈 상태의 기존 입력 제어 검사 17개도 통과했습니다.

최종 검토에서 자동 인식을 끈 상태의 수동 새 문자 요청이 입력을 지우는 문제를 수정했습니다. 꺼진 상태에서 입력을 보존하고 직접 편집해도 비활성 상태를 유지하는 추가 회귀 검사 2개가 통과했습니다.

### 설치 파일 검증

기존 설치 폴더 경로 유지, 이전 파일의 바이트 단위 백업, 다운로드 실패 시 원본 유지, 교체 실패 시 복구, 다른 앱 폴더 거부, 새 설치 및 임시 폴더 정리 검사가 통과했습니다.
설치 스크립트가 추출한 압축·최적화 소스로도 8개 이미지의 실제 OCR·React 입력·클릭 검사를 통과했습니다.

### 검증 한계

제공된 8개 이미지의 통과는 새 이미지 전체의 정확도를 보장하지 않습니다. 관리 정책이 실제 확장프로그램 설치를 차단하므로 Chrome 확장프로그램의 실제 설치 상태와 서비스 워커/offscreen 수명 주기는 미검증입니다. 재시도 검사에서는 서버 응답을 모의했으며 실제 예매 서버에 인증을 제출하지 않았습니다.

## 1.0.1 이미지 디코딩 수정 검증

새 첨부 HTML의 캡차 DOM은 기존 구조와 같으며, data URL의 MIME은 JPEG지만 실제 바이트는 정상 PNG(210×70)였습니다. PNG CRC·압축 스트림 검사가 모두 통과했습니다.

오류 문구가 발생하는 `HTMLImageElement.decode()` 대기 경로를 제거하고 실제 파일 시그니처에 맞는 Blob을 `createImageBitmap`으로 디코딩합니다. `OffscreenCanvas`로 전처리하며 정상 및 제한시간 후 늦게 생성된 bitmap을 해제합니다. 기존 10초 제한은 늘리지 않았습니다.

- 실제 Chromium/WASM에서 기존 세 이미지와 새 `CTXCNA`의 OCR 성공. 두 전처리 결과가 각 이미지에서 일치했습니다.
- 같은 CSP의 일반 페이지 및 숨긴 iframe에서 검증했습니다. DOM 이미지 생성자를 오류로 바꾸고 `Image.decode()`를 영원히 대기하도록 해도 새 디코더는 정상 작동했습니다.
- 실제 React 입력창·background/offscreen 메시지 핸들러 구성요소 테스트에서 네 이미지가 각 한 번 입력·클릭되었고, 멈춘 `Image.decode()`가 호출되지 않았음을 확인했습니다. Chrome API는 테스트 대역입니다.
- 손상된 입력, 디코딩 시간 초과 후 자원 해제, 미처리 예외·외부 네트워크 요청이 없음을 확인했습니다.

설치 스크립트 검증: 기존 1.0.0 폴더의 경로 유지·바이트 단위 백업, 다운로드 실패 시 원본 유지, 교체 실패 시 복구, 다른 앱 폴더 거부, 새 설치 및 임시 폴더 정리 테스트가 통과했습니다. 업데이트한 실제 설치 파일로 네 이미지의 OCR·React 입력 테스트를 다시 통과했습니다.

원인에 관한 한계: 일반 페이지와 숨긴 iframe의 기존 디코더에서는 사용자가 겪은 시간 초과를 재현하지 못했습니다. 실제 Chrome offscreen 문서의 렌더링 의존성이 원인이라는 설명은 추정입니다. 이 환경은 관리 정책으로 확장프로그램 설치가 차단되어 실제 설치 상태와 예매 서버 인증은 미검증입니다.

## 1.0.0 검증 기록

### 확인 완료

1. 업로드한 두 HTML을 파싱하여 모달·이미지·입력창·footer 버튼 위치를 확인했습니다. HTML의 실행 스크립트는 사용하지 않았습니다.
2. 실제 Chromium + Tesseract.js 5.1.1 WASM에서 `TTDUBN`, `UTDUUP`를 확인했습니다. 두 전처리 결과가 각 이미지에서 일치했습니다.
3. 동적 DOM 감지, native setter, input/change 이벤트, 버튼 활성화 대기, 중복 제출 방지, 모달 내부 버튼 제한, 이미지 교체 시 취소, 이미 입력한 값 보호, 인식 중 입력/입력 후 지우기 보호, 실행 중 끄기, 자동 클릭 끄기, 잘못된 OCR 결과 및 오류, 다시 시도, 숨겨진 모달, 비활성 버튼 보호를 포함하는 12개 시나리오가 통과했습니다.
4. 실제 React 18.3.1 controlled input, 실제 OCR 엔진, 실제 background/offscreen 메시지 핸들러를 함께 실행하는 로컬 구성요소 테스트가 통과했습니다. Chrome API만 테스트 대역으로 제공했습니다. 확장프로그램과 동일한 CSP를 적용했으며 외부 네트워크 요청이 없었습니다. `TTDUBN`, `UTDUUP`, 처음 대화의 `LUXQLS`가 각 한 번씩 입력·클릭되었고 관계없는 버튼은 클릭하지 않았습니다.
5. OCR worker 누락 시 오류와 재초기화 복구를 확인했습니다. JavaScript 구문 검사도 통과했습니다.

### 확인하지 못한 항목

테스트 환경의 Chromium 관리 정책 `ExtensionInstallBlocklist: ["*"]`가 확장프로그램 설치를 차단하므로 실제 설치 상태의 서비스 워커·offscreen 수명 주기 검증은 완료하지 못했습니다. 해당 정책은 변경하지 않았습니다.

실제 NOL 예매 서버에 접속하거나 인증을 제출하지 않았습니다. 저장 HTML에는 사이트 스크립트가 제거되어 서버 인증 성공 여부를 확인할 수 없습니다. 새 캡차에 대한 정확도는 검증한 세 이미지와 달라질 수 있습니다.
